# Feature Specification: 农场管家系统

**Feature Branch**: `001-featurename-farm-management-system`

**Created**: 2026-05-28

**Status**: Draft

**Input**: User description: "农场管家系统——涵盖农场生产要素管理、种植计划与流程管理、农事操作管理、库存管理、质量追溯体系、成本核算与产量预估六大模块的综合性农场信息化管理平台。"

## Clarifications

### Session 2026-05-28

- Q: 业务角色（农户/技术员/仓库管理员/销售员/财务人员）如何映射到宪法RBAC四角色（系统管理员/农艺师/操作员/观察者）？ → A: 收敛到4个宪法角色，通过"分工"字段区分业务职能
- Q: 关键告警通知渠道，v1 是否需要支持多渠道推送（短信/微信）？ → A: v1 仅内置系统内消息通知，预留扩展接口，短信/微信在 v1.1 补充
- Q: 生产批次的生命周期状态如何定义？采收完成后批次是否自动关闭？ → A: 简化状态：仅"进行中"和"已完成"两种状态，采收即自动标记完成，不允许重新打开
- Q: 农产品入库品质检测流程的具体判定标准是什么？与采收时的"品质等级"关系如何？ → A: 简化方案——仅"合格/不合格"二值判定，目视检查后勾选，不合格拒绝入库，不需要详细检测报告；采收时记录的品质等级作为参考，入库检测独立判定
- Q: 系统中的数值型业务阈值（重复提交间隔、盘点误差率、预警提前天数等）是否可配置？由谁配置？ → A: v1 中所有阈值均通过"系统设置"（仅管理员可访问）可配置；默认值按规范数值预置：重复提交间隔5分钟、盘点误差±2%、效期预警阈值30天、盘点锁定提前天数可设

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 农场生产要素管理 (Priority: P1)

农场管理员登录系统后，对农场的土地、人员、品种和设备四大生产要素进行全面的信息化登记与管理。管理员可将农场划分为多个区域（如A区、B区、C区），记录每个地块的面积和当前种植品种；建立包含200种以上蔬菜品种的品种库，并为每种作物配置详细的种植规范；登记员工信息并统计工时；登记农机具、灌溉设备和物联网设备，跟踪设备状态和维护计划。

**Why this priority**: 生产要素数据是所有后续模块的数据基础。没有地块、品种、人员和设备信息，种植计划、农事操作、库存和追溯等模块均无法运行。这是整个系统的"地基"。

**Independent Test**: 可在不依赖其他模块的情况下，独立完成地块、品种、人员、设备的增删改查操作，仪表盘正确展示农场总面积、已种植面积、闲置面积、品种数量、员工人数等指标。

**Acceptance Scenarios**:

1. **Given** 系统初次使用，**When** 管理员创建"A区"并添加地块"地块A01"，录入面积50亩，**Then** 系统保存成功，仪表盘中农场总面积更新为50亩，闲置面积为50亩。
2. **Given** 品种库为空，**When** 管理员录入蔬菜品种"番茄"，配置播种时间（3月-4月）、种植密度（每亩3000株）、施肥量（每亩50kg复合肥）、浇水频率（每2天一次），**Then** 品种保存成功，品种库数量+1。
3. **Given** 已存在员工"张三"，角色为操作员，**When** 管理员查看员工列表，**Then** 系统展示张三的姓名、分工、累计工时。
4. **Given** 已登记灌溉设备"水泵A01"，状态为"正常"，**When** 管理员设置下次维护日期为30天后，**Then** 系统在到达维护日期前3天推送维护提醒。
5. **Given** 地块A01状态为闲置、地块A02已种植10亩，**When** 管理员查看仪表盘，**Then** 仪表盘正确显示农场总面积、已种植面积10亩、闲置面积为地块A01面积。

### User Story 2 - 农事操作管理 (Priority: P1)

农户和技术员（系统角色为操作员或农艺师，业务分工为田间作业）在日常生产中，通过系统记录田间所有农事操作，包括播种/移栽、施肥、打药、灌溉/排水、除草/整枝、采收等。系统强制执行必填字段校验和防重复提交规则。

**Why this priority**: 农事操作记录是日常生产活动的数字化核心，是质量追溯的数据来源，也是成本核算的依据。没有它，系统只能做静态管理而无法支撑动态生产。

**Independent Test**: 可独立测试每种农事操作类型的录入、校验和查询功能，验证必填字段校验规则和5分钟重复提交拒绝规则。

**Acceptance Scenarios**:

1. **Given** 操作员登录系统，**When** 提交播种记录——品种:番茄、面积:5亩、时间:2026-05-28、操作人:李四（四要素齐全），**Then** 记录保存成功。
2. **Given** 操作员尝试提交播种记录，**When** 缺少"操作人"字段，**Then** 系统拒绝保存，提示"操作人不能为空"。
3. **Given** 操作员在10:00提交了施肥记录，**When** 同一操作人在10:03再次提交完全相同的施肥记录（同一地块、同一品种、同一肥料、同一用量），**Then** 系统拒绝保存，提示"重复提交，请勿在5分钟内重复提交相同记录"。
4. **Given** 操作员提交打药记录——农药:吡虫啉、用量:100ml、时间:2026-05-28、当前日期距预计采收日仅剩5天，**When** 系统检测到安全间隔期不足，**Then** 系统弹出强制预警"该农药安全间隔期为7天，当前距采收仅5天，禁止施用！"并拒绝保存。
5. **Given** 操作员提交采收记录——产量:500kg、品质等级:一级、去向:冷库、操作人:王五、采收时间:2026-05-28，**When** 提交保存，**Then** 记录保存成功，关联地块可种植面积自动释放。

### User Story 3 - 种植计划与批次管理 (Priority: P2)

农艺师根据节气和品种特性，制定并跟踪种植计划。系统根据当前节气自动推荐适宜种植的品种；为每种作物提供标准种植流程参考；按"地块+品种+时间"建立生产批次进行全程跟踪。

**Why this priority**: 种植计划将零散的生产要素和农事操作串联为有组织的生产流程，提升农场管理的计划性和科学性。但它依赖于P1模块的数据基础。

**Independent Test**: 可独立测试节气推荐功能、种植计划创建与调整、批次创建与跟踪、计划vs实际对比功能。

**Acceptance Scenarios**:

1. **Given** 当前节气为"谷雨"（4月19日前后），**When** 农艺师打开种植计划制定页面，**Then** 系统推荐显示适宜此时播种的品种列表（如番茄、辣椒、黄瓜等）。
2. **Given** 农艺师选择品种"番茄"并关联地块A01，**When** 创建种植计划，设定播种日期2026-05-01，**Then** 系统生成种植计划，并展示该品种的标准种植流程（播种→育苗→移栽→田间管理→采收）。
3. **Given** 种植计划已制定，**When** 农艺师将播种日期从5月1日调整为5月5日，选择调整原因为"连续降雨推迟"，**Then** 系统保存调整并记录调整原因和时间。
4. **Given** 地块A01于5月1日种植番茄，**When** 系统创建生产批次"P20260501-A01-番茄"，**Then** 该批次自动关联地块A01、品种"番茄"，后续该地块所有农事操作均归入此批次。
5. **Given** 批次"P20260501-A01-番茄"正在执行中，**When** 农艺师查看批次详情，**Then** 系统展示该批次从播种到当前的全部操作记录、当前生长阶段、预计采收日期。

### User Story 4 - 库存管理 (Priority: P2)

仓库管理员（系统角色为操作员，业务分工为仓库管理）对农产品和农资进行入库、出库、盘点全流程管理。系统强制执行品质检测、审批流程、FIFO原则、库存上下限校验等业务规则。

**Why this priority**: 库存管理直接关系到农场的物资流转和财务核算。但与P1、P2模块存在数据依赖（入库需要采收数据、出库需要品种和批次数据）。

**Independent Test**: 可独立测试所有入库类型、出库类型和盘点流程，验证品质检测卡控、审批流程、FIFO原则、数量合法性和库存预警等业务规则。

**Acceptance Scenarios**:

1. **Given** 采收完成，**When** 仓库管理员尝试将100kg番茄入库但未填写品质检测结果，**Then** 系统拒绝入库，提示"未通过品质检测，不得入库"。
2. **Given** 番茄一级50kg、二级30kg已入库，**When** 仓库管理员查看库存，**Then** 系统展示两个批次分开标记，不合并显示。
3. **Given** 销售人员（业务分工为销售）提交番茄一级30kg出库申请，**When** 主管（系统管理员或农艺师）审批通过后执行出库，**Then** 系统按FIFO原则优先扣减最早入库的批次库存。
4. **Given** 当前库存剩余番茄20kg，**When** 操作员尝试出库30kg，**Then** 系统拒绝出库，提示"库存不足，当前库存20kg"。
5. **Given** 操作员尝试入库数量为0的种子记录，**When** 提交保存，**Then** 系统拒绝保存，提示"入库数量必须大于0"。
6. **Given** 某农药有效期剩余20天，**When** 系统检查效期，**Then** 系统发出预警提示"农药XX有效期剩余20天，请尽快使用"。
7. **Given** 库存盘点启动，**When** 管理员指定非操作员张三执行盘点，**Then** 盘点期间系统暂停该库存项的出入库操作，盘点完成并误差率<2%后恢复。

### User Story 5 - 质量追溯体系 (Priority: P2)

系统自动整合从种子到销售全链条数据，为每个生产批次生成追溯码（二维码），消费者扫码即可查看该批次产品的全程信息。管理员可导出追溯报告（PDF格式）供认证或检查使用。

**Why this priority**: 质量追溯是食品安全和有机认证的核心需求，也是产品溢价的基础。它依赖前四个模块的数据汇总，但追溯逻辑本身可独立设计。

**Independent Test**: 可独立测试追溯数据的自动关联完整性、二维码生成与扫码展示、PDF报告导出、审计日志记录等功能。

**Acceptance Scenarios**:

1. **Given** 批次"P20260501-A01-番茄"已完成从播种到采收的全部流程，**When** 管理员为该批次生成追溯码，**Then** 系统生成唯一二维码，消费者扫码后展示：种子来源、品种、种植过程（所有农事操作）、投入品（肥料/农药）使用记录、环境监控数据、采收信息、销售去向。
2. **Given** 追溯码已生成，**When** 消费者扫描二维码，**Then** 页面展示该批次产品全链条信息，不包含内部成本等商业敏感数据。
3. **Given** 管理员在追溯页面点击"导出报告"，**When** 系统生成PDF格式追溯报告，**Then** 报告包含全部追溯数据且该导出操作记入审计日志。
4. **Given** 某条农事操作记录已保存3个月，**When** 任何用户尝试删除该记录，**Then** 系统拒绝删除，提示"追溯记录永久保存，不可删除"。
5. **Given** 管理员生成追溯报告，**When** 查看审计日志，**Then** 日志记录导出操作的导出人、导出时间、导出批次信息。

### User Story 6 - 成本核算与产量预估 (Priority: P3)

财务和管理人员（系统角色为系统管理员或操作员，业务分工为财务/管理）可进行多维度成本核算（按地块、批次、单位面积、单位产量）和利润分析。系统基于历史数据和当前生长状况预测产量，辅助销售决策。

**Why this priority**: 成本核算和产量预估是经营决策支持层面的功能，价值高但不妨碍日常生产运转，优先级可适当靠后。

**Independent Test**: 可独立测试各维度成本计算逻辑、收入统计、利润分析、产量预估模型等功能，无需依赖新功能模块的开发。

**Acceptance Scenarios**:

1. **Given** 地块A01本季种植番茄，已记录种子成本500元、肥料成本800元、农药成本300元、人工成本2000元、机械成本400元，**When** 管理员查看地块A01成本核算表，**Then** 系统显示总成本4000元，各项明细清晰列出。
2. **Given** 番茄产量2500kg、总成本4000元，**When** 系统计算单位产量成本，**Then** 显示每公斤成本1.6元。
3. **Given** 销售收入8000元、总成本4000元，**When** 系统计算利润，**Then** 显示利润4000元，利润率50%。
4. **Given** 历史上番茄亩产均在2000-2500kg，当前批次生长状况良好，**When** 系统预测本批次产量，**Then** 预估产量落在历史范围内并附置信度说明。
5. **Given** 两个地块种植相同品种但采用不同施肥方案，**When** 管理员对比两批次的产量和成本数据，**Then** 系统展示对比分析结果，帮助筛选更优的种植流程。

### Edge Cases

- 同一个地块在时间上重叠分配两个不同品种时，系统如何处理？（应拒绝：同一地块在同一时间段只能有一个活跃品种）
- 员工信息中包含身份证号等敏感数据时，如何确保隐私合规？（数据脱敏展示，仅管理员可见完整信息）
- 设备离线期间产生的农事操作如何补录？（支持离线补录，但须标记"补录"并记录实际补录时间与原始操作时间）
- 品种库中某品种的种植规范后续被修改，已创建的历史种植计划是否受影响？（历史计划不受影响，只影响新建计划）
- 库存盘点过程中发现实际库存与系统记录差异超过2%时，系统的盈亏处理流程是什么？（生成盈亏报告，管理员审核后调整库存，调整操作记入审计日志）
- 追溯码对应的产品批次已完成全部销售后，追溯信息是否仍然可查？（永久可查，追溯记录不可删除）
- 多人同时编辑同一地块信息时的并发冲突如何处理？（后提交者收到冲突提示，展示差异后选择覆盖或放弃）
- 采收时一个批次对应多个品质等级，如何拆分入库？（按品质等级分别生成子批次，独立入库和标记）

## Requirements *(mandatory)*

### Functional Requirements

**模块一：农场生产要素管理**

- **FR-001**: 系统 MUST 支持分区管理（如A区、B区、C区），每个分区下可创建多个地块，记录每个地块的面积、当前种植品种、闲置面积。
- **FR-002**: 系统 MUST 支持建立包含200种以上蔬菜品种的品种库，每种品种可配置播种时间、种植密度、施肥量、浇水频率等种植规范。
- **FR-003**: 系统 MUST 支持人员管理，包括登记员工信息、系统角色（系统管理员/农艺师/操作员/只读观察者）、业务分工（田间作业/仓库管理/财务/销售等）、统计每位员工的工时和效率。
- **FR-004**: 系统 MUST 支持设备资源管理，登记农机具、灌溉设备、物联网设备，记录设备状态和维护计划，维护到期前3天推送提醒。
- **FR-005**: 系统 MUST 在仪表盘中展示农场总面积、已种植面积、闲置面积、品种数量、员工人数等关键统计指标。

**模块二：种植计划与流程管理**

- **FR-006**: 系统 MUST 根据当前节气自动推荐适宜种植的蔬菜品种，辅助农艺师制定种植计划。
- **FR-007**: 系统 MUST 为每种作物配套标准种植流程模板，覆盖播种、育苗、移栽、田间管理、采收各环节。
- **FR-008**: 系统 MUST 实时对比种植计划与实际执行情况，支持计划调整并记录调整原因。
- **FR-009**: 系统 MUST 按"地块+品种+时间"规则自动创建生产批次，对该批次进行全生命周期跟踪管理。
- **FR-010**: 系统 MUST 支持生成种植计划表和批次生产档案。

**模块三：农事操作管理**

- **FR-011**: 系统 MUST 支持播种/移栽操作记录，必填字段为品种、面积、时间、操作人，四要素缺一不可，缺一项整条记录拒绝保存。
- **FR-012**: 系统 MUST 支持施肥操作记录，包含肥料品类、用量、施用时间、当时天气状况。
- **FR-013**: 系统 MUST 支持打药操作记录，包含农药品类、用量、施用时间；系统 MUST 自动计算安全间隔期，临近采收时强制预警并拒绝保存。
- **FR-014**: 系统 MUST 支持灌溉/排水操作记录，包含水量、时长、操作人、作物当前生长阶段。
- **FR-015**: 系统 MUST 支持除草/整枝操作记录，包含操作内容、涉及面积、操作人、操作时间。
- **FR-016**: 系统 MUST 支持采收操作记录，包含产量、品质等级、去向、操作人、采收时间。
- **FR-017**: 系统 MUST 强制执行操作限制规则：同一操作人 N 分钟内（默认5分钟，可在系统设置中配置）重复提交相同记录时，拒绝重复提交。
- **FR-018**: 所有农事操作记录 MUST 关联到对应的生产批次和地块；系统 MUST 在首次农事操作提交时自动将批次状态从"待执行"切换为"进行中"；批次状态为"已完成"时，系统 MUST 拒绝该批次下任何新的农事操作记录提交；采收操作提交后系统 MUST 自动将批次状态切换为"已完成"。

**模块四：库存管理**

- **FR-019**: 系统 MUST 支持农产品入库，采收后入库须经品质检测（合格/不合格二值判定，目视检查勾选），检测不合格拒绝入库；采收时记录的品质等级（一级/二级等）作为参考，入库检测独立判定；同一品种不同批次分开存放、分开标记。
- **FR-020**: 系统 MUST 支持农资采购入库，记录物资名称、规格、数量、供应商、采购人。
- **FR-021**: 系统 MUST 支持销售出库，须经主管审批，农户无权直接出库；遵循先进先出（FIFO）原则。
- **FR-022**: 系统 MUST 支持农资领用出库，记录物资名称、数量、领用人、用途、关联地块、时间。
- **FR-023**: 系统 MUST 支持定期盘点（月度、季度、年度）和循环盘点（每周抽查1-2个地块），盘点由仓库管理员手动发起，须由非操作员执行（交叉盘点），盘点期间暂停出入库。
- **FR-024**: 系统 MUST 在盘点误差率绝对值超过配置阈值（默认±2%，即误差率绝对值 > 2% 时触发，可在系统设置中配置）时启动盈亏处理流程。
- **FR-025**: 系统 MUST 支持低库存预警（库存低于安全阈值自动提醒，阈值可在系统设置中配置）和农资效期预警（剩余有效期不足 N 天强制提示，默认30天，可配置）。
- **FR-026**: 系统 MUST 强制执行出库数量不大于当前库存的硬性限制，入库数量必须大于0，违反则拒绝保存。

**模块五：质量追溯体系**

- **FR-027**: 系统 MUST 为每个生产批次自动关联种子来源、种植过程、投入品使用、环境监控数据（来自 IoT 传感器或手动录入）、采收、销售全链条数据。
- **FR-028**: 系统 MUST 支持为每个批次生成唯一追溯码（二维码），消费者扫码可查看全程追溯信息（不含商业敏感数据）。
- **FR-029**: 系统 MUST 支持导出追溯报告（PDF格式）供认证或检查使用，导出操作记入审计日志。
- **FR-030**: 追溯记录 MUST 永久保存，不可删除、不可篡改；追溯深度覆盖地块、批次、操作记录、操作人、时间戳五个层级。
- **FR-031**: 追溯报告仅管理员可导出。

**模块六：成本核算与产量预估**

- **FR-032**: 系统 MUST 支持按地块统计种子、肥料、农药、人工、机械等各类成本。
- **FR-033**: 系统 MUST 支持按生产批次统计总成本和单位成本。
- **FR-034**: 系统 MUST 支持按单位面积（每亩）和单位产量（每公斤）进行成本核算。
- **FR-035**: 系统 MUST 支持收入核算，统计销售订单、销售收入、客户付款状态。
- **FR-036**: 系统 MUST 支持利润核算（利润=收入-成本），支持按地块、批次、品种多维度分析。
- **FR-037**: 系统 MUST 基于历史数据和当前生长状况进行产量预估，辅助销售决策。
- **FR-038**: 系统 MUST 支持分析不同批次产量表现，筛选高效种植流程。
- **FR-039**: 系统 MUST 生成地块成本核算表、批次成本分析表、产量预估报告、利润分析报表。

### Key Entities

- **地块 (Plot)**: 农场土地的基本管理单元，属性包含区域归属、面积、当前种植品种、状态（已种植/闲置）、土壤类型。
- **品种 (Variety)**: 蔬菜品种信息，属性包含品种名称、类别、种植规范（播种时间、种植密度、施肥量、浇水频率、生长周期）、安全间隔期配置。
- **人员 (Staff)**: 农场员工信息，属性包含姓名、系统角色（系统管理员/农艺师/操作员/只读观察者，决定权限级别）、业务分工（田间作业/仓库管理/财务/销售等，标识职能领域）、累计工时、联系方式。
- **设备 (Equipment)**: 农机具和物联网设备信息，属性包含设备类型、编号、状态、维护计划、关联地块。
- **种植计划 (Planting Plan)**: 种植安排，属性包含关联地块、品种、计划播种日期、计划采收日期、标准流程引用、状态（待执行/执行中/已完成/已调整）。
- **生产批次 (Production Batch)**: 按"地块+品种+时间"生成的唯一生产单元，属性包含批次号、关联地块、品种、播种日期、预计采收日期、当前状态（进行中/已完成）、追溯码。状态转换规则：首次农事操作提交后状态变为"进行中"；采收操作提交后状态自动变为"已完成"；"已完成"批次不允许再录入农事操作记录。
- **农事操作记录 (Farming Operation)**: 田间作业记录，按类型分（播种/施肥/打药/灌溉/除草/采收），属性包含操作类型、地块、批次、时间、操作人、操作详情、天气状况。
- **库存记录 (Inventory Record)**: 物资库存信息，属性包含物资类型（农产品/农资）、品种/名称、规格、数量、批次、存放位置、入库时间、品质等级。
- **出入库记录 (Stock Transaction)**: 库存流水，属性包含类型（入库/出库）、关联库存、数量、操作人、审批人、时间、去向/来源。
- **盘点记录 (Stocktake Record)**: 盘点结果，属性包含盘点类型、执行人、盘点时间、库存项、系统数量、实际数量、误差率、处理结果。
- **追溯记录 (Traceability Record)**: 不可变的质量追溯数据聚合，属性包含批次号、全链条关联数据引用、追溯码、生成时间。
- **成本记录 (Cost Record)**: 成本核算数据，属性包含关联地块/批次、成本类型、金额、发生时间。
- **销售记录 (Sales Record)**: 销售订单信息，属性包含客户信息、品种、数量、等级、销售时间、金额、付款状态、经手人。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 管理员可在30分钟内完成农场全部生产要素（地块、品种≥200、人员、设备）的初始化录入。
- **SC-002**: 操作员可在2分钟内完成一次标准农事操作记录（播种/施肥/打药等）的录入和提交。
- **SC-003**: 种植计划推荐的品种与当前节气匹配准确率达到95%以上（定义：用户实际使用推荐品种完成种植计划的比例 ≥ 95%）。
- **SC-004**: 库存盘点全流程（锁定→盘点→结果录入→差异处理）可在30分钟内完成一个地块的盘点。
- **SC-005**: 追溯码扫码后3秒内展示该批次全链条信息。
- **SC-006**: 成本核算报表（地块/批次/单位面积/单位产量）在数据完整的情况下，生成时间不超过10秒。
- **SC-007**: 系统拒绝保存非法数据（必填项缺失、数量越界、重复提交、权限不足）的准确率达到100%。
- **SC-008**: 90%的日常操作（查看数据、记录操作、查询库存）在3次触达内完成。
- **SC-009**: 产量预估与实际产量偏差不超过±15%。
- **SC-010**: 系统支持至少50名用户同时在线操作，核心功能响应正常。
- **SC-011**: 所有数值型数据采集与计算计量精度误差不超过±0.5%。

## Assumptions

- 本系统面向中型规模农场（200-500亩），不假设存在多个独立农场租户（单租户架构）。
- 节气数据使用中国农历二十四节气标准定义，预置在系统内，不依赖外部API。
- 品种库的200+蔬菜品种及种植规范数据由用户自行录入或导入，系统提供Excel模板批量导入功能。
- 物联网传感器数据接入为可选项，系统在无传感器接入时仍可正常使用（环境监控模块数据可手动录入）。
- 追溯码（二维码）的生成和消费者扫码页面为系统内置功能，不依赖外部二维码服务平台。
- PDF追溯报告使用服务端生成方案，不依赖客户端浏览器打印功能。
- 用户角色默认为四种：系统管理员、农艺师、操作员、只读观察者；支持后续自定义扩展。
- 系统默认支持中文界面，计量单位为中国通用农业单位（亩、公斤、克、毫升等）。
- 成本核算和利润分析基于已录入的成本和收入数据，不连接外部财务系统。
- 通知推送（维护提醒、库存预警、效期预警）v1 默认为系统内消息通知；短信/微信推送接口已预留，v1.1 版本实现。
